The load balancer

One fixed address in front of things that keep changing.

What it isWhy you need oneWhy ECS needs oneThe words

01What it is

A load balancer is a machine that AWS runs for you. It has one fixed address. Browsers send requests to that address, and it passes each request on to one of your running copies, then returns the answer. The copies behind it can come and go; the address in front does not change.

02Why you need one, even with one copy

On Day 1 the browser talked straight to the container: http://18.168.202.250:8000. That address was the machine's. It worked because there was one machine and it never changed. Three things break as soon as that stops being true.

03Why ECS needs one

ECS starts and stops tasks all the time: a crash, a deploy, scaling up at nine in the morning. Every new task has a new address. Something has to be told about each one, and told to forget the old ones. That something is the load balancer, and ECS does the telling.

In Express Mode ECS creates the load balancer for you and keeps this list itself. On Day 7, when we build the service without Express Mode, the target group and listener become things we write down in CDK.

04The words

Application Load Balancer
The kind we use. It understands HTTP: paths, headers, cookies. AWS also sells a Network Load Balancer, which works at the TCP level and is for things that are not HTTP.
listener
What the load balancer listens on: a port and a protocol. Ours is HTTPS on 443, with the certificate attached. A listener has rules that say which target group gets the request.
target group
The list of addresses that may receive traffic, with a health check attached. ECS adds and removes tasks from it. "Target" is the word for one entry: for us, one task's IP and port 8000.
health check
The load balancer asks each target GET /health on an interval. A target that fails a few in a row stops getting traffic; ECS then replaces it. A new target gets no traffic until it passes.
draining
When a target is being removed, the load balancer stops sending new requests but lets the current ones finish, for up to a set time. This is why a deploy does not cut off a chat mid-stream.
what it costs
About $18 a month to exist, plus a small amount per request. Up to 25 Express Mode services in one account share one, so the price is per account more than per app.

The one sentence to remember: the load balancer is the one address that never changes; ECS keeps its list of live tasks up to date, so tasks can crash, deploy and scale without anyone outside noticing.
