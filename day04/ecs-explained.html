ECS, and which compute service to pick

What the parts are called, what Fargate is, and how to choose between ECS, EC2, Lambda and the rest.

01What ECS is

ECS, Elastic Container Service, runs containers for you and keeps them running. You describe what should be running: which image, how many copies, how much CPU and memory. ECS finds room for them, starts them, watches them, and replaces any that die. On Day 1 you were the thing doing all of that, by hand, on one machine.

02The parts, and what each is called

Five words cover all of ECS. Every console page, every CDK class and every error message uses them.

task definition
A versioned file that says what to run: image, CPU, memory, ports, environment variables, secrets, log settings. It is a recipe, not a running thing. Every change makes a new revision: oracle:8 after oracle:7.
task
One running copy of a task definition. It has an IP address, a start time, logs, and a life: it starts, runs, and stops. Two copies of the Oracle are two tasks.
container
What Docker runs. A task usually has one, named Main in Express Mode. It can have more, for example a log forwarder next to the app, called a sidecar.
service
The instruction "keep N tasks of this definition running, and connect them to this load balancer". The service is what replaces a crashed task, what scales, and what performs a deployment when the definition changes.
cluster
A named group that services and tasks belong to. It is where capacity is attached. One account can have many; the Oracle uses one called default.
capacity provider
Where the tasks physically run: Fargate, your own EC2 instances, or ECS Managed Instances. A cluster can have more than one. Section 03.

03Where the tasks run: Fargate, EC2, Managed Instances

08How to choose

Six questions, asked in this order, get you to the right row of the table most of the time.

The six questions, in words

  1. 1

    Shape. Does it answer requests and never finish (a service), finish on its own (a job), or run once per event (a function)? This one question rules out most of the menu.

  2. 2

    Duration and size. Lambda stops at 15 minutes and 10 GB of memory, and reloads your model on every cold start. A job that runs for an hour, or a model that takes 30 seconds to load, is not a Lambda.

  3. 3

    Hardware. GPU, lots of memory, local NVMe disk, a specific CPU. Any of these takes Fargate and Lambda off the table and leaves EC2-backed options.

  4. 4

    Traffic pattern. Steady all day favours per-hour billing (EC2-backed). Bursty or mostly idle favours per-second (Fargate) or per-request (Lambda). A service with a minimum of one task always costs at least one task.

  5. 5

    Team. Who will be on call for it? Kubernetes is a skill set. EC2 patching is a chore. Fargate and Lambda remove work; they do not remove all of it.

  6. 6

    Portability. If it must also run on Azure or on-premises, a container is the unit that moves, and Kubernetes is the runtime that exists everywhere. Lambda code and SageMaker endpoints do not move.

Cost is a shape, not a number. Per request (Lambda) is zero when idle and expensive when busy. Per task-second (Fargate) is flat per copy. Per instance-hour (EC2) is flat and cheapest per unit if you keep it full. Draw the traffic of your app across a day and the right billing shape is usually obvious.

10Mistakes to expect

  • Treating Fargate as a separate service. It is where ECS tasks run. Every Fargate task has a task definition, a cluster, and usually a service; you will meet all of them in the console.
  • Running a job as a service. The script exits 0, ECS reads that as a crash, starts it again, and your retraining runs in a loop all night. Jobs are standalone tasks.
  • Choosing EKS because it is "the standard". It is standard for teams that have it. For one application and no Kubernetes experience, it adds a control plane, a bill and a skill set for nothing.
  • Putting a model that loads in 30 seconds on Lambda. Every cold start pays that 30 seconds. Users see it. A service that keeps one task warm does not.
  • Comparing EC2 and Fargate on price alone. The EC2 number excludes patching, HTTPS, scaling, replacement, and the evening it breaks. Compare what each costs in your time as well.
  • Asking for a GPU on Fargate. Not offered. The task definition is rejected, or the service never places a task. Use the EC2 launch type or Managed Instances.

The one sentence to remember: ECS keeps N copies of a task definition running; Fargate is one place they can run; and for anything that is a container, serves requests, and needs no GPU, ECS on Fargate is the default and every other choice needs a reason.
